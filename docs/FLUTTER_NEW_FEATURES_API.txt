FEATURE 1 — REGISTRATION (Phone mandatory + disposable email block)
================================================================================

POST /api/flutter/auth/register

Body (JSON):
{
  "name": "Rahul Sharma",
  "email": "rahul@gmail.com",
  "phone": "+919876543210",      // REQUIRED now
  "password": "MyPass123"
}

Success 201:
{
  "success": true,
  "message": "Registration initiated. OTP sent to your email.",
  "email": "rahul@gmail.com"
}

Errors:
  400 — phone missing/invalid
  400 — disposable email (temp-mail blocked)
  409 — email or phone already registered

Flutter UI changes:
  - Phone field mandatory (not optional)
  - Show error if temp email used
  - Continue to OTP screen after success

FEATURE 2 — PROFILE SUBMIT CHECKLIST (Before profile verification)
================================================================================

Before user can submit profile, ALL items must pass:

  ✓ All required fields filled
  ✓ Valid phone on account
  ✓ At least 1 profile photo
  ✓ At least 1 family/lifestyle photo (in addition to profile photo)
  ✓ ID document uploaded (Aadhaar/PAN/Passport etc.)
  ✓ Profile marked 100% complete

Required profile fields:
  gender, dob, height, religion, education, profession, country, city, aboutMe

--- POST submit profile for verification ---

POST /api/flutter/profile/submit
Headers: Authorization: Bearer <token>
Body: {} (empty)

Success 200:
{
  "success": true,
  "message": "Profile submitted for admin review. You will be notified once approved.",
  "code": "PENDING_APPROVAL"
}

(User sees: "Profile submitted! We will notify you once verified.")
Note: API message may say "admin review" — show user-friendly text in Flutter UI.

Error 400 — PROFILE_INCOMPLETE:
{
  "error": "Profile incomplete. Fill all required fields before submitting.",
  "code": "PROFILE_INCOMPLETE",
  "missingFields": ["aboutMe"],
  "requiredFields": [...]
}

Error 400 — SUBMIT_REQUIREMENTS_NOT_MET:
{
  "error": "Your profile does not meet the verification requirements yet...",
  "code": "SUBMIT_REQUIREMENTS_NOT_MET",
  "checklist": [...],
  "errors": [...]
}


--- Upload APIs used for checklist ---

POST /api/flutter/upload/photo
  Content-Type: multipart/form-data
  Fields: photo (file), isMain ("true" / "false")

POST /api/flutter/upload/family-photo
  Content-Type: multipart/form-data
  Fields: photo (file), caption (optional), memberCount (optional)

POST /api/flutter/upload/document
  Content-Type: multipart/form-data
  Fields: document (file), type ("Aadhaar Card" | "PAN Card" | etc.)

FEATURE 5 — REPORT ABUSE + AUTO-HIDE
================================================================================

POST /api/flutter/report

Body:
{
  "targetId": "<reported_user_id>",

}

Success 201:
{
  "success": true,
  "id": "report-uuid",

  "autoHidden": false,
  "reportCount": 1

When target gets 3+ reports (handled by backend automatically):
{
  "success": true,
  "message": "Report submitted. This profile has been temporarily hidden pending review due to multiple community reports.",
  "autoHidden": true,
  "reportCount": 3
}

Flutter: Show toast — "Report submitted". No admin UI needed in app.

FEATURE 6 — COUPON CODES (NEW / FIXED)
================================================================================

--- Quick validate (homepage / premium screen — no auth) ---

POST /api/flutter/coupons/validate
Body:
{
  "code": "SAVE20"
}

Success 200:
{
  "valid": true,
  "discountPct": 30,
  "code": "SAVE20"
}

Errors: 404 invalid, 410 expired or usage limit reached


--- Apply coupon with plan price (checkout screen — auth required) ---

POST /api/flutter/payment/apply-coupon
Headers: Authorization: Bearer <token>

Body:
{
  "code": "SAVE20",
  "planId": "GOLD",
  "months": 3,              // optional: 1, 3, 6, 0=lifetime
  "durationDays": 90        // optional: alternative to months
}

Success 200:
{
  "code": "SAVE20",
  "discountPct": 30,
  "originalPrice": 4497,
  "finalPrice": 3148,
  "durationDays": 90,
  "isAgentRef": false,
  "plan": "GOLD"
}

Also accepts agent referral codes (5% discount, isAgentRef: true)


--- Create payment order with coupon ---

POST /api/flutter/payment/create-order
Headers: Authorization: Bearer <token>

Body:
{
  "plan": "GOLD",
  "couponCode": "SAVE20",    // optional
  "months": 3,               // optional: 1, 3, 6, 0=lifetime
  "durationDays": 90         // optional
}

Success 200 (paid plan):
{
  "orderId": "MILAN_XXXXXXXX_1234567890",
  "paymentSessionId": "session_...",
  "orderAmount": 3148,
  "plan": "GOLD",
  "durationDays": 90,
  "couponApplied": "SAVE20"
}

Success 200 (100% discount — instant activation):
{
  "instantActivation": true,
  "plan": "GOLD",
  "orderAmount": 0,
  "premiumExpiry": "2026-08-28T..."
}

Flutter flow:
  1. User enters coupon → call apply-coupon → show discounted price
  2. User pays → call create-order with same couponCode
  3. Open Cashfree SDK with paymentSessionId
  4. After payment → call verify endpoint


--- Verify payment ---

POST /api/flutter/payment/verify
Headers: Authorization: Bearer <token>

Body:
{
  "orderId": "MILAN_XXXXXXXX_1234567890",
  "plan": "GOLD"
}

Success (paid):
{
  "status": "PAID",
  "isPremium": true,
  "premiumExpiry": "2026-08-28T..."
}

Note: Receipt email is sent automatically by backend after successful payment.

--- Real-time chat (Socket.IO) — RECOMMENDED ---

Connect: wss://vivahdwar.com  path: /api/socket
Auth: { token: "<JWT>" }  in handshake auth OR Authorization header

Events to EMIT:
  room:join          { roomId }
  room:leave         { roomId }
  message:send       { roomId, message }
  message:read       { roomId, readerId }
  typing:start       { roomId, userId }
  typing:stop        { roomId, userId }
  location:update    { roomId, msgId, latitude, longitude }
  user:online        { userId }

Events to LISTEN:
  message:receive    — new message in room
  message:read       — peer read messages
  typing:start       — peer typing
  typing:stop
  location:update    — live location moved
  users:online       — online user ids list

Flutter: Use socket_io_client package. REST API for history; socket for live.

FEATURE 12 — SUPPORT CHATBOT (AI Help + Live Support)
================================================================================

In-app help assistant — FAQ, plans, payment, profile help.
NOT member-to-member chat. Free for all users.

APIs: /api/chatbot/* (shared with website — no /api/flutter/ prefix)
No JWT required for guests. Pass userId when user is logged in.

--- Init (call once on app start — creates DB tables if needed) ---

POST /api/chatbot/init
Body: {}

Success: { "ok": true }


--- Start or restore session ---

GET /api/chatbot/session?sessionId={guestSessionId}
  — restore guest session from local storage

POST /api/chatbot/session
Body: { "action": "new", "userId": "<optional logged-in user id>" }

Success:
{
  "ok": true,
  "sessionId": "uuid",
  "status": "bot",          // bot | live | ended
  "messages": [ { id, sessionId, sender, content, createdAt } ],
  "storageKey": "vd-support-session"
}

Other session actions:
  { "action": "escalate", "sessionId": "...", "userId": "..." }
    → Connect to live support team (human reply via backend)

  { "action": "attach", "sessionId": "...", "userId": "..." }
    → Link guest session to logged-in user

  { "action": "end", "sessionId": "..." }
    → End support chat


--- Send message to bot ---

POST /api/chatbot/message
Body:
{
  "sessionId": "uuid-or-null-for-new",
  "message": "What are premium plans?",
  "userId": "<optional logged-in user id>"
}

Success 200:
{
  "sessionId": "uuid",
  "status": "bot",
  "botReply": "Our premium plans are...",
  "intent": "premium",
  "followUps": [
    { "label": "View Plans", "text": "premium plans" },
    { "label": "Talk to Agent", "text": "__escalate__" }
  ],
  "actions": [],
  "confidence": 0.85,
  "suggestLiveAgent": false
}

When status is "live" — botReply is null; support team will reply.
Poll GET /api/chatbot/message?sessionId=... every 3-5 seconds for new messages.

Special followUp text "__escalate__" → call POST session action escalate.


--- Get chat history ---

GET /api/chatbot/message?sessionId={sessionId}

Success:
{
  "messages": [
    { "sender": "user",    "content": "...", "createdAt": "..." },
    { "sender": "bot",     "content": "...", "createdAt": "..." },
    { "sender": "support", "content": "...", "createdAt": "..." }
  ],
  "session": { "id", "status", "language", ... }
}


--- Bot capabilities (intents) ---
  greeting, premium, payment, profile, verification, safety,
  refund, login, search, agent (live support), fallback

Supports English + Hindi (auto-detected).

Flutter UI tips:
  - Save sessionId in SharedPreferences (key: vd-support-session)
  - Show followUp buttons from API response
  - Poll messages every 3-5 sec when status === "live"
  - Floating help button → open Support ChatBot screen
