FLUTTER SOCKET.IO INTEGRATION GUIDE
=====================================
Server: Socket.IO (same server as REST API)
Path:   /api/socket
URL:    wss://yourdomain.com  (same domain as API)


PACKAGE (pubspec.yaml)
-----------------------
dependencies:
  socket_io_client: ^2.0.3+1


CONNECTION (with JWT auth)
---------------------------
import 'package:socket_io_client/socket_io_client.dart' as IO;

IO.Socket socket = IO.io(
  'https://yourdomain.com',
  IO.OptionBuilder()
    .setPath('/api/socket')
    .setTransports(['websocket'])
    .setAuth({'token': 'Bearer $jwtToken'})   // <-- your login token
    .enableAutoConnect()
    .enableReconnection()
    .setReconnectionAttempts(10)
    .setReconnectionDelay(1000)
    .build(),
);

socket.onConnect((_) {
  print('Socket connected: ${socket.id}');
});

socket.onDisconnect((_) => print('Socket disconnected'));
socket.onConnectError((err) => print('Connect error: $err'));


EVENTS YOU CAN LISTEN TO
--------------------------

1. users:online
   Fired when any user comes online/goes offline.
   Data: List<String> — list of online user IDs
   socket.on('users:online', (data) { ... });

2. users:lastseen
   Fired when a user disconnects with their last seen time.
   Data: Map { userId: isoDateString }
   socket.on('users:lastseen', (data) { ... });

3. message:receive
   Fired when a new message arrives in a room you joined.
   Data: { id, chatRoomId, senderId, receiverId, content, type, isRead, createdAt }
   socket.on('message:receive', (data) { ... });

4. message:read
   Fired when the other person reads your messages.
   Data: { roomId, readerId }
   socket.on('message:read', (data) { ... });

5. typing:start
   Fired when someone starts typing in a room.
   Data: { userId, roomId }
   - Inside chat screen: join room first via room:join, then listen here.
   - On chat LIST screen: listen globally (no room:join needed) — server forwards
     typing events to your personal user:{yourId} room automatically.
   socket.on('typing:start', (data) { ... });

6. typing:stop
   Fired when someone stops typing.
   Data: { userId, roomId }
   socket.on('typing:stop', (data) { ... });

7. interest:received
   Fired when someone sends you an interest.
   Data: { fromUser: { id, name, ... } }
   socket.on('interest:received', (data) { ... });

8. location:update
   Fired when a live location message is updated.
   Data: { msgId, latitude, longitude }
   socket.on('location:update', (data) { ... });


EVENTS YOU EMIT
----------------

1. Join a chat room (call this when opening a chat screen)
   socket.emit('room:join', roomId);

2. Leave a chat room (call this when closing chat screen)
   socket.emit('room:leave', roomId);

3. Send a message (emit after REST API POST succeeds)
   socket.emit('message:send', {
     'roomId': roomId,
     'message': {
       'id': msgId,
       'chatRoomId': roomId,
       'senderId': myUserId,
       'receiverId': otherUserId,
       'content': 'Hello!',
       'type': 'TEXT',
       'isRead': false,
       'createdAt': DateTime.now().toIso8601String(),
     }
   });

4. Mark messages as read
   socket.emit('message:read', {
     'roomId': roomId,
     'readerId': myUserId,
   });

5. Typing indicator — start
   socket.emit('typing:start', {
     'roomId': roomId,
     'userId': myUserId,
   });

6. Typing indicator — stop
   socket.emit('typing:stop', {
     'roomId': roomId,
     'userId': myUserId,
   });

7. Notify interest sent (optional — server also handles via REST)
   socket.emit('interest:notify', {
     'toUserId': receiverUserId,
     'fromUser': { 'id': myId, 'name': myName },
   });


RECOMMENDED FLOW FOR CHAT SCREEN
----------------------------------
1. Open chat screen
   → socket.emit('room:join', roomId)
   → Load messages via REST: GET /api/flutter/chat/{roomId}?page=1&limit=20

2. User types
   → socket.emit('typing:start', { roomId, userId })
   → socket.emit('typing:stop', { roomId, userId })  (after 1-2s debounce)

3. User sends message
   → POST /api/flutter/chat  (REST — saves to DB)
   → On success: socket.emit('message:send', { roomId, message })
   → Other user receives via: socket.on('message:receive', ...)

4. User reads messages
   → REST auto-marks read on GET /api/flutter/chat/{roomId}
   → socket.emit('message:read', { roomId, readerId: myUserId })
   → Other user receives: socket.on('message:read', ...)

5. Close chat screen
   → socket.emit('room:leave', roomId)


CHAT LIST — TYPING INDICATOR
------------------------------
You do NOT need to join every room on the chat list screen.
Just stay connected with JWT auth (server auto-joins user:{yourId}).

Listen globally:
  socket.on('typing:start', ({ userId, roomId }) {
    // Mark roomId as "userId is typing"
  });
  socket.on('typing:stop', ({ userId, roomId }) {
    // Clear typing state for roomId
  });

When opening a specific chat, still emit room:join for live messages.


NOTES
------
- JWT token is passed in handshake auth — no need to emit 'user:online' manually
  (server auto-registers Flutter users on connect)
- Web users still use 'user:online' event — both work simultaneously
- Socket server runs on same port as Next.js (no separate port needed)
- Reconnection is automatic with exponential backoff
