FLUTTER API CHANGES DOCUMENTATION
==================================
Date: May 7, 2026


1. /api/flutter/profile  (app/api/flutter/profile/route.js)
------------------------------------------------------------

GET - Changes:
- Ab SELECT * se profile fetch hoti hai — siblings, caste, gotra, diet, complexion, bodyType,
  fatherOccupation, motherOccupation, familyType, familyStatus, partnerAgeMin, partnerAgeMax,
  horoscopeSign, nakshatra, manglik aur baaki saari fields ab response me aayengi.

- premiumPlanDetails: Ab subscription + planconfig table se join karke aata hai.
  Agar user ka active subscription hai toh null nahi aayega.
  Fields: id, plan, status, amount, currency, startDate, endDate,
          displayName, permissions (parsed array), durationDays, description

- profileComplete: Ab 27 fields se calculate hota hai (pehle sirf 9 tha).
  Fields counted: gender, dob, height, weight, religion, caste, motherTongue, education,
  profession, income, country, state, city, aboutMe, maritalStatus, diet, complexion,
  bodyType, fatherOccupation, motherOccupation, siblings, familyType, familyStatus,
  horoscopeSign, manglik, name, photo (at least 1)
  GET pe bhi recalculate + DB me sync hota hai.

- ?userId=<id> query param support:
  Kisi bhi user ki profile dekh sakte ho. Response me ye extra flags milenge:
    interestSent      — { id, status } ya null  (tumne use interest bheja hai ya nahi)
    interestReceived  — { id, status } ya null  (usne tumhe interest bheja hai ya nahi)
    isBlocked         — true/false
    isReported        — true/false
    isShortlisted     — true/false
  Profile view bhi automatically record hoti hai (profileview table).

PUT - Changes:
- profileComplete ab PUT ke baad bhi DB se recalculate + sync hota hai.
- Response me premiumPlanDetails bhi include hai.

3. /api/flutter/dashboard  (app/api/flutter/dashboard/route.js)  — NEW API
---------------------------------------------------------------------------

GET /api/flutter/dashboard
Auth: Bearer token required

Response:
{
  counts: {
    interest_sent,        // total interests tumne bheje
    interest_received,    // total interests tumhe mile
    profile_views,        // total baar tumhari profile dekhi gayi
    messages,             // total messages tumhe mile
    matches,              // total accepted interests (matches)
    today_interest_sent,  // aaj bheje interests
    today_profile_views,  // aaj tumhari profile kitni baar dekhi gayi
    today_messages        // aaj mile messages
  },
  new_matches_today: [    // aaj join kiye users (opposite gender, same religion) — max 10
    { id, name, isPremium, isVerified, verificationBadge, profile: {...}, photos: [...] }
  ],
  recommended_matches: [  // premium first, phir profileComplete ke basis pe — max 10
    { id, name, isPremium, isVerified, verificationBadge, profile: {...}, photos: [...] }
  ],
  pending_interests: [    // tumhe mili interests jo abhi PENDING hain — max 10
    { id, name, ..., interest: { id, message, createdAt } }
  ],
  recent_activity: [      // jinne tumhari profile dekhi — max 10
    { id, name, ..., viewed_at }
  ]
}


4. /api/flutter/push/token  (app/api/flutter/push/token/route.js)  — NEW
--------------------------------------------------------------------------

POST /api/flutter/push/token
Auth: Bearer token required
Body: { "token": "<FCM device token from FirebaseMessaging>" }

Call after login and on token refresh. Without this, push notifications will not work.

Responses:
  201 — { "success": true, "message": "FCM token registered successfully" }
  200 — { "success": true, "message": "Token already registered" }
  401 — Unauthorized / invalid JWT
  400 — { "error": "FCM token is required" }


5. Push notification payloads (FCM data)
-----------------------------------------

type: NEW_PROFILE — sent when admin approves a matching profile

Paid premium user (isPremium=true only, NOT free trial):
  data: { type, accessLevel: "full", profileId, profileName, profileCity, screen: "profile" }
  → Open profile screen

Free user OR free trial user:
  data: { type, accessLevel: "locked", screen: "premium", reason: "subscription_required" }
  → Open premium/plans screen — do NOT show profileId

type: CHAT_MESSAGE
  data: { type, roomId, senderId }
  → Open chat room (requires isPremium OR freeTrialActive)

7. DELETE /api/flutter/interest/:id — Withdraw Interest (Sender)
------------------------------------------------------------------

Jab tumne kisi ko interest bheja ho aur status PENDING ho, sender interest wapas le sakta hai (web jaisa).

DELETE /api/flutter/interest/:id
Auth: Bearer token
Params: id = interest UUID (interestId)

interestId kahan se mile:
  - GET /api/flutter/profile/:userId  →  interestSent.id  (jab interestDirection = "sent", status = PENDING)
  - GET /api/flutter/interest?type=sent  →  item.id

Responses:
  200 — {
    "success": true,
    "message": "Interest withdrawn successfully",
    "receiverId": "uuid"
  }
  400 — { "error": "Only pending interests can be withdrawn" }   (ACCEPTED/REJECTED par nahi)
  404 — { "error": "Not found" }   (galat id ya tum sender nahi ho)

Side effects:
  - interest row delete
  - receiver ke "New Profile Interest" notification hat jati hai
  - dubara POST /api/flutter/interest se interest bhej sakte ho

Flutter UI flow:
  1. Profile par interestSent.status == "PENDING" → "Withdraw Interest" button
  2. DELETE with interestSent.id
  3. Local state: interestSent = null, interestStatus = null


8. DELETE /api/flutter/block — Unblock User
--------------------------------------------

DELETE /api/flutter/block
Auth: Bearer token
Body: { "blockedId": "uuid" }

Responses:
  200 — { "success": true, "blocked": false }
  404 — { "error": "User is not blocked" }

Note: POST /api/flutter/block still toggles block/unblock (backward compatible).

9. Chat Live Location — Flutter API + Implementation Prompt
------------------------------------------------------------

=== REST APIs ===

A) Send static (one-time) location:
POST /api/flutter/chat/{roomId}
Body:
{
  "type": "LOCATION",
  "latitude": 28.6139,
  "longitude": 77.2090,
  "locationType": "current"
}

B) Send live location (WhatsApp style):
POST /api/flutter/chat/{roomId}
Body:
{
  "type": "LOCATION",
  "latitude": 28.6139,
  "longitude": 77.2090,
  "locationType": "live",
  "locationExpiry": "2026-05-25T18:00:00.000Z"   // now + 1h / 8h etc.
}

Response message object fields:
  type: "LOCATION"
  latitude, longitude
  locationType: "current" | "live"
  locationExpiry: null | ISO datetime

C) Update live coords (sender only, every 15-30 sec):
PATCH /api/flutter/chat/location/{msgId}
Body: { "latitude": 28.6140, "longitude": 77.2091 }
Responses:
  200 — { id, chatRoomId, latitude, longitude, locationType, locationExpiry, isLive, isExpired, isActive }
  410 — Live location expired
  403 — Only sender can update

D) Poll fallback (receiver OR sender):
GET /api/flutter/chat/location/{msgId}
Same response as PATCH 200.

=== Socket ===

Listen globally (chat screen + chat list):
  socket.on('location:update', (data) {
    // data: { msgId, roomId, latitude, longitude }
    updateMapMarker(data.msgId, data.latitude, data.longitude);
  });

PATCH API already broadcasts location:update — client emit optional.

=== Flutter UI Rules ===

1. Message type LOCATION render karo:
   if (msg.type == 'LOCATION') show LocationBubble

2. Static location (locationType == 'current'):
   - Map thumbnail + pin
   - Tap → open Google Maps: https://www.google.com/maps?q=lat,lng

3. Live location (locationType == 'live'):
   - Check isActive = locationExpiry > now
   - Show green "LIVE" badge + pulsing dot if active
   - Show "ENDED" / grey if expired
   - Show time left: locationExpiry - now

4. Sender flow (sharing live):
   - Get GPS → POST live location message → save msgId
   - Start Geolocator.getPositionStream or Timer every 20s:
       PATCH /api/flutter/chat/location/{msgId}
   - Stop when locationExpiry reached or user taps Stop

5. Receiver flow:
   - Show map at msg.latitude / msg.longitude
   - socket.on('location:update') → if data.msgId matches, move pin
   - Optional: GET poll every 30s if socket disconnected

6. Chat list preview:
   lastMessage.type == 'LOCATION' → show "📍 Location" or "📡 Live Location"

=== Packages suggested ===
  geolocator: ^latest
  google_maps_flutter: ^latest   (or flutter_map + openstreetmap)
  socket_io_client: ^2.0.3+1

=== Example duration helper ===
DateTime expiry = DateTime.now().add(Duration(hours: 1));
locationExpiry: expiry.toUtc().toIso8601String()
